# ADR-002: Selection of Java Spring Boot for Enterprise Backend

## Status
Accepted

## Date
2026-07-27

## Context
The Vetra backend must serve as an enterprise-grade, HIPAA/GDPR compliant healthcare surveillance system capable of processing high-volume telemetry, managing complex relational entities (Users, Animals, Diagnoses, Appointments), providing RBAC security, and scaling horizontally across cloud environments.

## Decision
We choose **Java Spring Boot 3.x (Spring Security, JPA/Hibernate, Spring Cloud)** as the backend framework.

## Rationale
1. **Enterprise Reliability & Ecosystem**: Spring Boot provides production-ready security, transaction management, REST APIs, and microservices integration out of the box.
2. **Type Safety & Maintainability**: Java's strong typing prevents runtime schema errors in critical health record transactions.
3. **Spring Security & OAuth2/JWT**: Comprehensive RBAC authorization enforcement for `FARMER`, `VETERINARIAN`, and `ADMINISTRATOR` roles.
4. **ORM & Database Integration**: Native integration with JPA/Hibernate for complex entity mapping and PostGIS spatial queries.
5. **High Concurrency & Scalability**: Multi-threaded execution model ideal for handling concurrent disease report submissions and real-time alerts.

## Consequences
- Requires JVM runtime deployment and memory tuning.
- Verbose boilerplate mitigated via Lombok and DTO abstractions.
