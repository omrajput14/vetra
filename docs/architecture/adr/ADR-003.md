# ADR-003: Selection of PostgreSQL with PostGIS Extension for Spatial Analytics

## Status
Accepted

## Date
2026-07-27

## Context
Livestock health surveillance depends heavily on spatial data: farm locations, veterinarian coverage zones, disease outbreak clusters, quarantine radiuses, and live tracking of mobile veterinarians. The database must perform fast geospatial indexing, radius queries, and containment calculations.

## Decision
We choose **PostgreSQL with the PostGIS extension** as the primary relational and geospatial database.

## Rationale
1. **Industry Standard Geospatial Engine**: PostGIS provides advanced spatial data types (`GEOMETRY`, `GEOGRAPHY`) and native spatial functions (`ST_DWithin`, `ST_Buffer`, `ST_Contains`).
2. **High-Performance Radius Calculation**: Indexed spatial queries (`GiST` / `SP-GiST`) enable instant computation of 5km/10km/50km quarantine zones and nearby veterinarian discovery.
3. **ACID Compliance**: Full relational integrity for financial transactions, medical records, and ownership histories alongside spatial data.
4. **Integration with Spring Data JPA**: `hibernate-spatial` integrates seamlessly with Spring Boot entities.

## Consequences
- Requires PostgreSQL PostGIS extension installation in database instances.
- Spatial index optimization (`ST_SetSRID`, EPSG:4326) must be adhered to in migrations.
