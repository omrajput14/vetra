# ADR-001: Selection of Flutter for Cross-Platform Mobile Client

## Status
Accepted

## Date
2026-07-27

## Context
Vetra requires a high-performance, responsive mobile application targeting rural farmers and field veterinarians. The client application must support offline caching, camera hardware integration for AI disease scanning, QR code reading, interactive map rendering, and smooth animations across Android and iOS devices.

## Decision
We choose **Flutter (Material 3, Riverpod, GoRouter)** as the primary technology stack for the client application.

## Rationale
1. **Single Codebase Efficiency**: Develop once in Dart and deploy natively to Android and iOS with high code reuse (95%+).
2. **Predictable 60/120 FPS UI Rendering**: Impeller graphics engine ensures smooth rendering of complex dashboards, cards, maps, and custom animations in low-end rural devices.
3. **Robust Hardware Integration**: Strong plugin support for camera sensors (AI scanning), camera QR reading, local filesystem storage, and location services.
4. **Offline-First Capability**: Direct integration with local storage engines (Hive/SQLite) and background sync runners.
5. **Role & State Architecture**: Riverpod provides compile-safe dependency injection and state management, while GoRouter enforces strict declarative role-based routing.

## Consequences
- Requires Dart expertise for team members.
- App binary size is slightly larger than native Java/Kotlin, but manageable (<30 MB baseline).
