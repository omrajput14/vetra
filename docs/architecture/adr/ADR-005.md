# ADR-005: Role-Based Isolated Dashboards and Declarative Security Guards

## Status
Accepted

## Date
2026-07-27

## Context
Vetra serves distinct user roles (`UserRole.farmer`, `UserRole.veterinarian`, `UserRole.administrator`). Farmers focus on herd health and vet booking; Veterinarians focus on clinical diagnostics, triage, and prescription management; Administrators oversee system metrics and user verification. Mixing role UI widgets or allowing unauthorized navigation causes confusion and security vulnerabilities.

## Decision
We enforce **100% role-isolated dashboard views and GoRouter declarative security redirect guards**.

## Rationale
1. **Clear Mental Model**: Each role experiences a tailored, zero-clutter application UI.
2. **Zero Cross-Role UI Leakage**: Farmers cannot view vet clinical triage options or diagnostic entry forms; Vets cannot manage farmer-specific herd registry screens.
3. **Declarative Route Guards**: `GoRouter` redirect callbacks evaluate the active user role session (`authRoleProvider`) on every route change, redirecting unauthorized navigation back to appropriate role dashboards.
4. **Extensibility for Administrator Role**: Future admin features (`/admin/*`) are registered with guards for seamless enablement in V2.

## Consequences
- Requires maintaining distinct bottom navigation components (`FarmerBottomNavigation` vs `VetBottomNavigation`).
- All navigation actions must pass through GoRouter.
